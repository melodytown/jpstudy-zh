# 课程验收

对 `units.json` 独立复算六条规则，输出 `lint-report.md` 给人看、`lint-report.json` 给机器看。任何一条不过，整份课程不合格。

## 独立复算

`06-lint` 只读 `words.json` / `units.json` / `grammar.json`，自己重建"词→首次教学单元"的表，**不复用 `05-curriculum` 的内部状态**。这是刻意的：如果验收和生成共用同一份中间结果，生成逻辑错了验收也会跟着错，规则就失去意义。

## 规则

| 规则 | 目标 | 当前 |
|---|---|---|
| R1 句子可得性 | 每句的未知词数 = 0 | 0 / 12951 |
| R2 单单元负载 | 新词 ≤20、语法 ≤3、新汉字 ≤15（stage ≤2） | 0 违例 |
| R3 语法覆盖与顺序 | 不重复、不按级别倒退 | 0 重复、0 倒退 |
| R4 螺旋复现 | 每词在教它之后的课里至少再现一次的比例 ≥80% | 82.4% |
| R5 句长趋势 | 每级别后 1/3 中位 ≥ 前 1/3 中位 −1 | 全部通过 |
| R6 每日预算 | 每天 ≤25 min（8s/卡 + 6s/句） | 峰值 21.1 min |

R2 的汉字预算只对 stage ≤2 生效：N3 之后不再逐课限新汉字。R6 的回访排期用 `1,2,4,8,16,32` 天近似 FSRS 的到期分布，不是从 `ts-fsrs` 推的——它估的是"最坏情况的一天有多长"，允许偏保守。

## 判定与报告

- 六条全过才 `PASS`；报告只写目标、实测、通过与否，超限项附样例（前 10 条）。
- R4 的失败原因必须拆分上报："一次都没被排进任何课" vs "只在教它的那一课出现"——前者是容量/语料问题，后者是挑选策略问题，修法完全不同。
- 报告不写真实时间（固定 epoch），同输入重跑逐字节相同，可以直接 diff。
