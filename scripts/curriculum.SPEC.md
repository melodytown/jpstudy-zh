# 难度与排课

决定"哪个词先学、哪句话放哪一课"。这是整个项目的核心算法，也是唯一需要读得懂才能改的地方。

## 难度分 D

`D = 40·jlptNorm + 25·freqScore + 15·formCost + 20·zhNorm`，归一到 0–100。

- **jlptNorm**：N5=0、N4=0.25、N3=0.5、N2=0.75、N1=1。
- **freqScore**：JPDB 排名取对数再除以全表最大对数（0=最常见）；N5/N4 没有排名，用牌组级别内主观序 `levelOrder×6` 当代理；两者都缺给中性值 0.55。
- **formCost**：读音长度（每 8 字 0.35，封顶）+ 促音/拗音/长音 0.2 + 片假名外来语 0.2 + 纯假名词 0.15 + 汉字词带音便 0.1（封顶 1）。
- **zhNorm**（中文母语者修正，负值＝更容易）：纯假名 +0.6、≥2 汉字 −0.5、单汉字 −0.15、命中同形异义 +1.0、多字名词再 −0.1；`(raw + 0.75) / 2.35` 后裁剪到 0..1。

权重与各系数的来源是项目初期的一份方案文档（未入库），**不是**拟合真实学习数据得到的；那份文档已不再维护，本 spec 与 `04-difficulty.mjs` 才是权威记录。改动它们属于产品判断，不是 bug 修复：改完要重看各级别最易/最难词与 `lint-report.md` 的 R5／R6。

`stage` 直接由词本身的级别决定（N5=1 … N1=5），D 只负责阶段内排序——所以"课程阶段"和"词的 JLPT 级别"是同一件事，不存在两套进度。

## 04b：语料补全

Tatoeba 的 jpn-cmn 句对，只保留"句中每个词都在词表里"的句子：长度 5–34、至少 2 个词、同句去重、出现词表外汉字整句丢弃。分词由 `text-libs` 的 DP 分词器做，注音用词典读音＋活用器反查屈折形，再按假名对齐切 ruby。

## 05：排课

**第一遍，单元骨架与词分配。** 每个级别按语法点数除以 2 得到语法块，按词数除以 20 得到词块，单元数取两者较大者（语法教完就只剩词汇课）；每单元词数 = 向上取整整除，保证不超过 20。

- 同级内按 D 排序；**例句资源少的词（语料命中 < 3 句）整体 +60 后置**，否则第一课会全是"五日／七日"这类只存在于词表里的词。
- 每个级别的前几课在 10 分难度带内优先"例句多"的词，让开篇读得动。
- stage ≤ 2 时按新汉字预算排：一课最多引入 15 个新汉字，超出的词顺延。

**第二遍，例句归位。** 关键式子是 `requiredUnit(句) = max(tu(句中每个词表词))`，`tu` = 该词被教的单元。把句子放到 `requiredUnit`，则此后任何一课读它都不会有生词——R1 由此成立，且"螺旋复现"天然发生。再做句长上限（按 stage 22/28/34/40/46 字）。

**挑选（贪心集合覆盖）。** 每单元候选池 = 所有 `req ≤ 本课` 且未被用过的句子。先取最多 3 句含本课新词的教学句，其余按 `复习旧词数×3 − 0.02×句长 − 4×新词数` 排序填到 24 句。目标是让旧词尽快在后续课里再露一次，而不是简单按 `req` 排队。

**已确认的限制**：R4 复现率 82.4%，上限来自每课例句容量（24 句）而不是语料量；提高 `targetSentencesPerUnit` 或继续补语料都能线性改善，但会推高 R6 的每日预算。
