# 上游接入

把三份上游数据变成一份带例句的词表，并复制课程需要的音频。

## 上游与许可

| 仓库 | 提供 | 许可 |
|---|---|---|
| `5mdld/anki-jlpt-decks` | 中文释义、音调、牌组例句、词/句音频 | CC BY-NC 4.0 |
| `evanclan/OpenJLPT` | 语法点、汉字表、jmdict_id、英文义 | CC BY-SA 4.0 |
| `mifunetoshiro/kanjium` | 活用表（对拍用）、音调补缺 | CC BY-SA 4.0 |

非商用、自用；本项目不分发上游数据本身，只分发自己生成的课程产物。许可约束是这条流水线只服务个人学习的原因。

## 01：牌组解析

`notes.csv` 是 Anki 导出的 TSV，39 列，列序来自上游 `diff_notes.py` 的 `FIELD_NAMES`——**不是猜的**，改解析先回去看上游定义。每行 4 个例句槽（词形／注音／简中／繁中／音频）。

- 词 id = `sha1(词形|读音)` 前 10 位；(词形, 读音) 相同视为同一条，重复行合并。
- `Sort` 列有两种口径：N5/N4 是 `级别.作者主观易→难序`，N3–N1 是 JPDB 词频排名（`999999` = 无数据）。两种都保留，难度分各取所需。
- 级别从标签里的 `N5`…`N1` 取；`1.` 前缀与级别不符记 `sortAnomaly`，只统计不纠正。
- 注音字段用 `text-libs` 解析成 `ruby` 段，并用 `plain` 与原句回环比对，不一致计数上报（目前为 0，出现即数据问题）。
- 音频字段是 `[sound:xxx.mp3]`，只留文件名，缺文件计入 `quality.missingMediaRefs`。

## 02：join 补强

join 顺序固定：`(词形, 片假名归平假名后的读音)` 精确 → `(词形)` 唯一命中 → 清洗掉 `〜` 与括号后再试。同形多读音时用读音二次筛选，仍歧义就放弃——宁可缺，不可错配。

- 命中率约 51.4%。没命中的词 `en`/`jmdictId` 留 null。
- 级别交叉校验容忍 ±1 级：牌组是真题向、OpenJLPT 是 Waller 表，两者口径不同，不计为错误。
- kanjium 音调只用于交叉核对：实测能补的为 0，音调缺口来自牌组本身。

**已确认的限制**：约一半词没有英文义与 jmdict_id，属上游覆盖度，不做二次补全。

## 07：音频打包

按 `units.json` 的 stage 收集该阶段的音频，复制到 `public/media/`，并写 `manifest.json`（文件名 → 字节数）。比较大小决定是否重拷，所以重复跑是增量。

收集范围必须覆盖 08 会暴露的每一个 `audio` 字段，否则单元页会出现点了没声音的喇叭：

- 新词的发音；
- **单词卡片下面例句的发音**（08 每个词只放前 2 句）；
- 本单元精读例句的发音。

`08-site` 反向兜底：生成站点数据时用 `public/media` 的实际文件列表过滤，没打包到的音频写成 `null`（N4–N1 目前就是这样，喇叭不显示而不是坏链接）。

默认只打包 stage 1（N5，2071 个文件 / 27MB）；`npm run media:all`（`--stage=5`）出全量：26408 个文件 / 345MB / 0 缺失。全量只用于官方发布包的 CI 构建，不提交进仓库。
